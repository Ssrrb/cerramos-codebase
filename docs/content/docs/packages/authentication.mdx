Authentication lives in `@repo/auth` and uses [Better Auth](https://better-auth.com/) on top of the shared `@repo/database` package.

`@repo/auth` owns shared auth capabilities for the repo: server and client helpers, handlers, provider wiring, and reusable sign-in and sign-up components.
It does not own app route mounting in `apps/app` or feature-specific authorization rules that belong with the owning domain.

This repo ships with:

- Better Auth for email/password, Google OAuth, and session management
- Drizzle for the auth tables and domain tables
- Neon Postgres as the backing database
- Shared sessions across `app` and `web` when your deployment uses a common parent domain and `BETTER_AUTH_COOKIE_DOMAIN`

## In-App

`@repo/auth` exposes:

- server helpers like `auth()`, `currentUser()`, and `requireSession()`
- a Better Auth handler exported from `@repo/auth/handlers`
- client helpers like `signIn`, `signUp`, `signOut`, and `useSession`

The app still consumes compatibility helpers such as `<OrganizationSwitcher>` and `<UserButton>`, but they are now backed by Better Auth and the repo’s `commerceId` field.

## Routes

The auth handler is mounted only in the `app` app:

```tsx title="apps/app/app/api/auth/[...all]/route.ts"
export { DELETE, GET, PATCH, POST, PUT } from "@repo/auth/handlers";
```

All sign-in and sign-up UI in the workspace talks to this handler.

## Data Model

Auth data is stored in the Better Auth tables:

- `user`
- `session`
- `account`
- `verification`

The `user` table also carries app-specific fields such as `role`, `commerceId`, and `customerId`, which lets the app keep using `orgId` compatibility as an alias for `commerceId`.

## Webhooks

External auth webhooks are disabled in this repo. Authentication is first-party and DB-backed, so auth state is derived directly from the Better Auth tables instead of a third-party webhook stream.

## Local Development

Set the auth variables in your local env files:

```bash
BETTER_AUTH_SECRET="change-me-with-a-real-secret"
BETTER_AUTH_URL="http://localhost:3000"
AUTH_GOOGLE_CLIENT_ID="..."
AUTH_GOOGLE_CLIENT_SECRET="..."
BETTER_AUTH_COOKIE_DOMAIN=".example.com" # production only
```

For local development on `localhost`, you do not need `BETTER_AUTH_COOKIE_DOMAIN`.
