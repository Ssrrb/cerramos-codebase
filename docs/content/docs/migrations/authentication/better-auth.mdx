This repo’s Better Auth migration uses the same stack that now ships in the workspace:

- Better Auth in `@repo/auth`
- Drizzle in `@repo/database`
- Neon Postgres as the database

## 1. Add the auth package dependencies

Install Better Auth and make sure `@repo/auth` depends on `@repo/database`:

```package-install
npm install better-auth --filter @repo/auth
```

## 2. Add the auth environment variables

Set these in `apps/app/.env.local` and `apps/web/.env.local`:

```bash
BETTER_AUTH_SECRET="replace-with-a-long-random-secret"
BETTER_AUTH_URL="http://localhost:3000"
AUTH_GOOGLE_CLIENT_ID="..."
AUTH_GOOGLE_CLIENT_SECRET="..."
NEXT_PUBLIC_AUTH_SIGN_IN_URL="/sign-in"
NEXT_PUBLIC_AUTH_SIGN_UP_URL="/sign-up"
NEXT_PUBLIC_AUTH_AFTER_SIGN_IN_URL="/"
NEXT_PUBLIC_AUTH_AFTER_SIGN_UP_URL="/"
```

In production, add:

```bash
BETTER_AUTH_COOKIE_DOMAIN=".yourdomain.com"
```

## 3. Mount the Better Auth handler in `app`

```tsx title="apps/app/app/api/auth/[...all]/route.ts"
export { DELETE, GET, PATCH, POST, PUT } from "@repo/auth/handlers";
```

The marketing site should reuse that same auth backend instead of hosting a second one.

## 4. Move your auth tables to Drizzle

Define the Better Auth tables in `packages/database/schema.ts`:

- `user`
- `session`
- `account`
- `verification`

Then keep any app-specific fields, such as `role`, `commerceId`, and `customerId`, directly on the `user` table through Better Auth `additionalFields`.

## 5. Rebuild the server and client helpers

The server package should:

- create a Better Auth instance with the Drizzle adapter
- enable email/password
- enable Google OAuth
- enable `nextCookies()`
- expose compatibility helpers like `auth()` and `currentUser()`

The client package should export:

```ts title="packages/auth/client.tsx"
const client = createAuthClient();

export const { signIn, signOut, signUp, useSession } = client;
```

## 6. Update auth UI and protected routes

Replace placeholder auth pages with real Better Auth flows:

- `signIn.email`
- `signUp.email`
- `signIn.social({ provider: "google" })`
- `signOut()`

If your app still expects an organization-like value, map that compatibility layer to your own domain model. In this repo, `orgId` maps to `commerceId`.

## 7. Keep middleware lightweight

Use cookie-based middleware checks for optimistic behavior, and keep the real authorization check in server components, actions, and route handlers:

```ts title="packages/auth/proxy.ts"
import { getSessionCookie } from "better-auth/cookies";

const sessionId = getSessionCookie(request, {
  cookiePrefix: "cerramos-auth",
});
```

## 8. Migrate existing users

If you already have legacy local auth tables, create a SQL migration that:

1. creates the Better Auth tables
2. copies `AppUser` rows into `user`
3. optionally copies old OAuth link rows into `account`
4. retires the old auth tables

This repo includes that cutover as a custom Drizzle SQL migration in `packages/database/drizzle/`.
