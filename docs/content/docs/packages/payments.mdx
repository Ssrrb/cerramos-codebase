Esta página describe la dirección de pagos de **este repo**, no el comportamiento por defecto de next-forge.

Cerramos está migrando desde Stripe hacia **Pagopar uPay** como procesadora principal de checkout.

## Dirección actual

- El proveedor objetivo del MVP es Pagopar uPay.
- El flujo debe mantenerse dentro de la URL y la interfaz de Cerramos.
- No queremos una experiencia de redirección a un checkout externo como camino base.
- Cerramos no captura datos sensibles directamente; esos datos deben pasar por componentes o flujos certificados del proveedor.

## Qué debe hacer la integración

- Crear una referencia de pago por pedido.
- Inicializar el cobro dentro del checkout propio.
- Registrar callbacks, webhooks y conciliaciones del proveedor.
- Normalizar los estados externos a los estados internos de pago.
- Permitir reversión, cancelación o devolución según soporte de Pagopar.

## Restricción de experiencia

- El comprador debe completar el pago sin salir del dominio de Cerramos en el flujo normal.
- Un redirect externo solo se acepta como contingencia o fallback del proveedor.
- La confirmación de pago no confirma por sí sola el pedido comercial.

## Webhooks y estado

La integración debe seguir tratando el estado del pago y el estado operativo del pedido como máquinas separadas. Los avisos del proveedor entran por webhooks o callbacks y luego se normalizan dentro del dominio de Cerramos.

Ver también: [inbound payment webhooks](/docs/packages/webhooks/inbound#payment-events).
