## Template boundaries to preserve

- Keep shared logic in the smallest appropriate `packages/*` boundary.
- Prefer server components unless a route needs client interactivity.
- Treat PostgreSQL as the always-on infrastructure.
- Use Drizzle for the database layer and Better Auth for authentication.
- Keep PagoPar/uPay payment behavior inside the payments integration surface.

## Cheki-specific rules

<AccordionGroup>
  <Accordion icon="split" title="Order state is not payment state">
    Order operations and payment settlement move independently. Do not collapse them into one model.
  </Accordion>
  <Accordion icon="message-circle" title="Messaging is not the source of truth">
    WhatsApp and other channels can notify users, but Cheki product surfaces own operational state.
  </Accordion>
  <Accordion icon="shopping-bag" title="One link, one offer">
    MVP purchase links represent one product or offer, and MVP orders contain one item.
  </Accordion>
</AccordionGroup>

## Useful commands

```bash
bun run dev
bun run build
bun run test
bun run check
bun run fix
bun run migrate
```

Use Turbo filters for scoped work, for example:

```bash
bun run build --filter @repo/database
bun run dev --filter app
```
