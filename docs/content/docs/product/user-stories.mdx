## Buyer stories

### 1. Comprar desde un chat sin volver a explicar todo

Como comprador que llega desde WhatsApp o Instagram, quiero abrir un link y encontrar el producto ya listo para comprar, para no volver al chat a pedir precio, variantes o pasos.

**Resultado esperado**

- veo el producto correcto y su precio
- entiendo si debo retirar o pedir entrega
- puedo seguir sin salir de la experiencia

### 2. Cerrar rápido desde el móvil

Como comprador móvil, quiero completar el flujo en una sola página clara, para no abandonar por cansancio de formularios.

**Resultado esperado**

- el flujo es corto y legible
- no aparecen campos irrelevantes
- el sistema prioriza velocidad y claridad

### 3. Comprar con datos confiables

Como comprador, quiero iniciar sesión antes de cerrar el pedido, para que mis datos estén completos y sean reutilizables en futuras compras.

**Resultado esperado**

- puedo entrar con Google o Apple
- el sistema recupera mis datos previos cuando corresponde
- entiendo qué información se guarda y por qué

### 4. Pagar sin sentir que la tienda desapareció

Como comprador, quiero que el pago ocurra dentro de la experiencia de Cerramos, para sentir continuidad y confianza.

**Resultado esperado**

- el flujo no me expulsa del sitio salvo contingencias del proveedor
- veo una promesa simple si hay cobro previo a confirmación
- el estado de mi pedido queda claro

## Merchant stories

### 5. Recibir pedidos listos para operar

Como comercio que vende por chat, quiero recibir un pedido estructurado en un panel interno, para dejar de reconstruir información desde mensajes sueltos.

**Resultado esperado**

- recibo producto, cantidad, variante y datos del comprador en un solo lugar
- sé si el pago fue requerido y en qué estado está
- puedo confirmar o cancelar sin ambigüedad

### 6. Mantener una sola verdad operativa

Como comercio, quiero que email y WhatsApp sean alertas y no la base operativa, para evitar estados contradictorios.

**Resultado esperado**

- el panel es la fuente de verdad
- las alertas son solo recordatorios
- el historial permanece auditable

### 7. Operar con riesgo controlado

Como plataforma, quiero limitar el prepago según la confianza del comercio, para proteger al comprador sin frenar el MVP.

**Resultado esperado**

- los comercios nuevos no cobran por adelantado sin condiciones
- si una tienda no confirma, el dinero vuelve cuando el proveedor lo soporta
- la política de riesgo es visible en el diseño del producto, no solo en la operación

## Acceptance anchors

Estas historias se consideran cubiertas cuando:

- un comprador puede cerrar un pedido de un solo producto desde móvil sin volver al chat
- el pedido llega al panel del comercio con datos suficientes para actuar
- el sistema mantiene separados estado operativo y estado de pago
- el flujo sigue siendo entendible aun cuando haya expiración, rechazo o reversión
